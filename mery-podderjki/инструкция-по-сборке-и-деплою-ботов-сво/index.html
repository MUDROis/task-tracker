1. Архитектура

                    ┌──────────────────────────────┐
  Пользователь VK ──▶│  VK Callback API             │
                    │  POST /vk                    │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │  Cloudflare Worker           │
                    │  <worker-name>               │
                    │  ├─ content.js  (база знаний)│
                    │  └─ worker.js   (логика)     │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────▼───────────────┐
  Пользователь MAX ─▶│  MAX Bot API (webhook)      │
                    │  POST /webhook               │
                    └──────────────────────────────┘

Ключевая идея: вся база знаний и логика ответов лежат в content.js и worker.js. Один и тот же Worker обслуживает оба канала:

КаналПутьЧто делает
ВКонтактеPOST /vkпринимает события Callback API, отвечает через messages.send
MAXPOST /webhookпринимает события Bot API, отвечает через POST /messages
ДиагностикаGET /debug?secret=…показывает журнал последних событий VK

Важно: Cloudflare Worker принимает только один файл в формате Service Worker. Поэтому content.js + worker.js склеиваются скриптом сборки в worker-sw.js.

5. Шаг 2. Сборка

Установка зависимостей (однократно)

Используется wrangler 3.80 (версия 4 на Windows падает с Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)).

Проверка и сборка

Что делает сборка (tools/build.mjs):

  1. убирает export из content.js;
  2. убирает import … from './content.js' из worker.js;
  3. превращает export default { async fetch(…) } в async function responder(…);
  4. добавляет addEventListener('fetch', …) и объект env из секретов;
  5. пишет результат в worker-sw.js.

Ожидаемый вывод: worker-sw.js собран: ~24000 символов.

❗ worker-sw.js — генерируемый файл. Правки вносить в content.js / worker.js, затем пересобирать.

7. Шаг 4. Настройка ВКонтакте

7.1. Включить сообщения и бота

  1. Сообщество → Управление.
  2. «Сообщения» → переключатель «Сообщения сообщества: включены».
  3. Блок «Возможности ботов» → Включены.
  4. (Опционально) «Добавить кнопку „Начать“».
  5. Сохранить.

7.2. Ключ доступа

  1. «Работа с API» → «Ключи доступа» → «Создать ключ».
  2. Права: «Управление сообществом» + «Сообщения сообщества».
  3. Скопировать ключ → VK_TOKEN.

7.3. Callback API

  1. «Работа с API» → вкладка «Callback API».
  2. Выпадающий список серверов (справа вверху) → «Сервер 1» (не другой сервер, если их несколько!).
  3. «Настройки сервера»:
    • Адрес: https://<worker-name>.<subdomain>.workers.dev/vk
    • Скопировать «Строку, которую должен вернуть сервер» → VK_CONFIRM
    • Скопировать «Секретный ключ» → VK_SECRET (или придумать свой, главное — одинаково в двух местах)
  4. Нажать «Подтвердить». Ожидаемо: зелёное «Адрес сервера успешно сохранён».
  5. «Типы событий» → включить «Сообщения» → «Входящее сообщение» (message_new). Сохранить.

7.4. Проверка

Написать сообществу «начать» (или /start) → должен прийти ответ с меню.

VK присылает нажатие кнопки «Начать» строчными буквами — бот это учитывает.

8. Шаг 5. Настройка MAX

8.1. Бот в MAX

  1. business.max.ru/self → раздел «Чат-боты» → «Создать».
  2. Логотип 500×500, название (1–59 символов), описание (до 200 символов).
  3. Дождаться модерации (до 48 рабочих часов).
  4. Из карточки бота скопировать токен → BOT_TOKEN.
  5. Убедиться, что статус — «Опубликован».

8.2. Webhook-подписка

MAX должен знать адрес, куда слать события:

Скрипт вызывает POST https://platform-api2.max.ru/subscriptions с событиями message_created, message_callback, bot_started и секретом.

Проверка подписки:

Ожидаемо: в списке есть https://<worker-name>.<subdomain>.workers.dev/webhook.

8.3. Проверка

Найти бота в MAX по никнейму или открыть https://max.ru/<никнейм> → /start.

Правка текстов

Все меры поддержки — в content.js, массив CATEGORIES:

Правила:

  • label должен содержать хотя бы одно слово из keywords — иначе кнопка в VK (текстовая) не сработает;

Затем (если меняли секреты) обновить их:

Добавление нового раздела

  1. Добавить объект в CATEGORIES (content.js).
  2. Если разделов станет больше 8 — проверить лимит кнопок VK (см. раздел 12).
  3. npm run test — тесты проверяют маршрутизацию всех кнопок.
  4. npm run deploy.

Если бот молчит — смотреть last_send:

ok: true — сообщение ушло. ok: false + data.error.error_code — причина отказа VK.
