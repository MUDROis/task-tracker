# Трекер задач

PWA-приложение для управления задачами команды с доской Kanban, делегированием и email-уведомлениями.

## Быстрый старт

1. Откройте `index.html` в браузере (или установите как PWA)
2. Войдите под учётной записью руководителя: 
3. Готово — доска с колонками «Срочные», «В работе» и «Отчёты» перед вами


## Роли

| Роль | Возможности |
|------|-------------|
| **Руководитель** (admin, Харитон) | Всё: создание и удаление задач и отчётов, делегирование, управление сотрудниками |
| **Сотрудник** | Создание задач, выполнение/возврат своих задач, редактирование своих задач, drag & drop |

## Доска Kanban

Три колонки:

- **🍳 Срочные** — задачи, требующие немедленного внимания (статус `urgent`)
- **▶️ В работе** — задачи в процессе выполнения (статус `in_progress`)
- **📄 Отчёты** — отчёты команды

Задачи можно перетаскивать между колонками «Срочные» и «В работе» (drag & drop).
Выполненные задачи и отчёты попадают в архив (кнопка **📁 Архив**).

## Задачи

### Создание
Нажмите **➕ Новая задача** (или **➕** в колонке «Отчёты») и заполните:
- **Заголовок** — название задачи (обязательно)
- **Описание** — детали (необязательно)
- **Приоритет** — низкий / средний / высокий
- **Срок выполнения** — дата дедлайна
- **Исполнитель** — назначить сотрудника

Переключатель **«Задача | Отчёт»** вверху модалки выбирает, что создавать.

### Создание двойным кликом по колонке
Двойной клик (двойной тап на мобильном) по пустому месту колонки сразу открывает
модалку создания с уже подставленным статусом колонки:
- **Срочные** → статус «Срочно»
- **В работе** → статус «В работе»
- **Отчёты** → режим «Новый отчёт»

### Редактирование
Дважды кликните по карточке задачи (двойной тап на мобильном). Автор и руководитель откроют редактирование, остальные — просмотр деталей.

### Действия на карточке
Кнопки действий скрыты. На компьютере наведите курсор на карточку, на телефоне коснитесь её (повторное касание скрывает).
- **✅ Выполнить** — переместить задачу в архив как выполненную
- **↩ Вернуть** — вернуть выполненную задачу в работу
- **📤 Делегировать** — назначить сотрудника (только для руководителя). На карточке появится стрелка **↗** в правом верхнем углу
- **🗑 Удалить** — удалить задачу (с подтверждением)

### Цвет боковой линии карточки (срок)
Левая полоска карточки задачи **и отчёта** показывает близость дедлайна.
Цвет пересчитывается автоматически раз в минуту — при пересечении порогов
(например, 17:00 в день сдачи или полуночи) линия меняется сама, без перезагрузки.

| CSS-класс | Значение | Цвет |
|-----------|----------|------|
| `strip-far` | Срок далеко: 4 суток и более (≥ 96 часов) | `#00a550` |
| `strip-close` | Ровно 2 суток (48 часов) до срока | `#4cbb17` |
| `strip-soon` | Ровно 1 сутки (24 часа) до срока — «завтра» | `#F1C40F` |
| `strip-day` | Наступил день сдачи (до времени сдачи или до 17:00) | `#ced23a` |
| `strip-red` | День сдачи, время 17:00 и позже — сегодня уже просрочено | `#E74C3C` |
| `strip-overdue` | Срок просрочен более чем на сутки | `#8B0000` |
| `strip-none` | Срок не задан или некорректный | `#64748b` |

Пороги смены цвета по времени: **4 суток → 2 суток → 1 сутки → день сдачи**.
В день сдачи до 17:00 линия жёлто-зелёная, с 17:00 — красная.

Подписи статусов срока (для подсказок и доступности): «Срок далеко (более 4 дней)»,
«Срок приближается (2 дня)», «Срок завтра (1 день)», «Срок сегодня»,
«Срок сегодня, просрочено (после 17:00)», «Срок просрочен (более 1 дня)», «Срок не задан».

### Линия выполненных записей в архиве
В архиве цвет линии фиксируется по итогу выполнения:
- `strip-ok` (зелёная `#00a550`) — выполнено в срок
- `strip-overdue` (бордовая `#8B0000`) — выполнено позже срока

## Делегирование

Нажмите **📤 Делегировать** на любой задаче (кроме выполненных). Выберите сотрудника из списка. Сотрудник получит email-уведомление о делегированной задаче.

Стрелка **↗** на карточке означает, что задача была делегирована через эту кнопку.

## Управление сотрудниками

Доступно только руководителю. Нажмите **👥 Управление** в панели инструментов.

### Добавление сотрудника
Заполните логин, пароль, email для уведомлений и выберите цвет на доске.

### Редактирование сотрудника
Нажмите **Изменить** у сотрудника. Можно изменить:
- Логин (обновится во всех задачах)
- Пароль (оставьте пустым без изменений)
- Email для уведомлений
- Аватар-эмодзи и цвет на доске (color-picker + палитра)

Если у сотрудника заполнено имя (`name`), оно отображается в задачах, отчётах,
архиве и списке сотрудников вместо логина.

### Удаление сотрудника
Нажмите **Удалить**. Если удаляете себя — произойдёт выход из системы.

## Уведомления по почте

Используется [EmailJS](https://www.emailjs.com) (бесплатно до 200 писем/мес).

### Настройка
1. Зарегистрируйтесь на [emailjs.com](https://www.emailjs.com)
2. Создайте **Email Service** (Gmail, Outlook и т.д.)
3. Создайте **Email Template** с переменными:
   - `{{to_email}}` — адрес получателя
   - `{{to_name}}` — логин получателя
   - `{{subject}}` — тема письма (подставляется заголовок задачи)
   - `{{task_title}}` — название задачи
   - `{{task_description}}` — описание задачи
   - `{{task_priority}}` — приоритет (Низкий/Средний/Высокий)
   - `{{task_due_date}}` — срок выполнения
   - `{{from_name}}` — кто делегировал/создал
   
   В поле **Subject** шаблона укажите `{{subject}}` — тогда тема письма будет равна заголовку задачи.
4. Впишите ключи в `app.js` (константы `EMAILJS_*`):
   ```js
   const EMAILJS_PUBLIC_KEY = 'ваш ключ';
   const EMAILJS_SERVICE_ID = 'ваш service id';
   const EMAILJS_TEMPLATE_ID = 'ваш template id';
   ```
5. Укажите email у каждого сотрудника в профиле

Уведомление отправляется при назначении исполнителя (создании задачи с исполнителем)
и при истекающем сроке задачи. Если email не указан — уведомление не отправляется.

## Экспорт и импорт Excel

### Экспорт
Нажмите **📤 Выгрузить Excel** — скачается файл `.xlsx` со списком всех задач.

### Импорт
Нажмите **📥 Импорт Excel** и выберите файл `.xlsx`. Задачи с совпадающим ID будут обновлены, новые — добавлены.

### Колонки файла
| Колонка | Описание |
|---------|----------|
| ID | Уникальный идентификатор |
| Заголовок | Название задачи |
| Описание | Текст задачи |
| Статус | Срочно / В работе / Выполнено |
| Создал | Кто создал |
| Исполнитель | Кому назначена |
| Приоритет | low / medium / high |
| Срок | Дата дедлайна |
| Создано | Дата создания |
| Обновлено | Дата последнего изменения |

## Технологии

- **HTML/CSS/JS** — без фреймворков
- **Firebase** — аутентификация (Auth) и хранение данных (Realtime Database)
- **PWA** — Service Worker для работы без интернета
- **localStorage** — только хранение сессии входа
- **SheetJS** — экспорт/импорт Excel
- **EmailJS** — email-уведомления
- **Node.js `node:test`** — тесты чистых функций (`tests/`)

## Структура файлов

```
task-tracker/
├── index.html               — разметка приложения
├── app.js                   — вся логика
├── style.css                — стили
├── js/helpers.js            — чистые функции расчёта сроков
├── firebase-config.js       — конфигурация Firebase (из .env)
├── firebase-config.example.js — шаблон конфигурации
├── manifest.json            — PWA-манифест
├── logo.png                 — логотип приложения
├── service-worker.js        — кеширование для offline
├── scripts/generate-config.js — генерация firebase-config.js из .env
├── tests/                — тесты (node --test "tests/*.test.js")
└── README.md                — эта инструкция
```

## Примечания

- Данные хранятся в **Firebase Realtime Database** (общие для команды). В `localStorage` хранится только сессия входа
- Проверка тех-конфигурации:
  - `npm run generate-config` — перегенерировать `firebase-config.js` из `.env`
  - `node --test "tests/*.test.js"` — запуск тестов
- При первом открытии приложение кеширует скрипты и работает без интернета
