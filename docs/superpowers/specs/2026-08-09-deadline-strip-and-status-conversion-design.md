# Полоска срока, статусы «задача ↔ отчёт» и подсветка выполненных

Дата: 2026-08-09

## Цель

1. Левая полоска карточки (задачи и отчёта) показывает близость срока выполнения: автоматический переход цвета от зелёного до бордового.
2. У всех задач появляется выбор статуса: «Срочно», «В работе», «Отчёт». Статус «Отчёт» превращает задачу в полноценный отчёт (с номером). Обратно отчёт может стать задачей.
3. В основной кнопке «➕ Новая задача» появляется возможность добавить и новый отчёт (переключатель «Задача | Отчёт» внутри модалки).
4. Выполненная задача/отчёт подсвечивается светло-зелёным фоном; если выполнена с нарушением срока — левая полоска остаётся бордовой.

## Текущее состояние

- Полоска карточки `.task-card` окрашивается по приоритету: `priority-high` → `#22c55e`, `priority-medium` → `#3b82f6`, `priority-low` → `#94a3b8` (style.css:370-378). Приоритет также записывается в класс карточки `priority-*`.
- Статус задачи — `urgent` / `in_progress` / `done`. В модалке задачи (`#taskStatus`) только «Срочные» и «В работе». Выполненные (`done`) уходят с доски в архив.
- Отчёты — отдельная коллекция `teams/<TEAM_ID>/reports` со статусом `active` (на доске) / `done` (архив) и номером `reportNumber`.
- Модалки: `#taskModal` и `#reportModal` — статичные HTML-блоки в `index.html`.
- Автопереход просроченных задач `in_progress → urgent` каждую минуту (`checkOverdueTasks`, app.js:328).

## Дизайн

### 1. Полоска-индикатор срока

Полоска отражает **только срок**. Приоритет полоску не окрашивает (остаётся в настройках и деталях задачи).

Расчёт — календарная разница дней между сегодня и днём срока (без времени суток):

```
calendarDaysUntil(dueDate):
  nowDay = start of today
  dueDay = start of day of dueDate
  return (dueDay - nowDay) / 86400000  (округлено)
```

| Дней до срока | Цвет | Класс | Hex |
|---|---|---|---|
| > 5 | зелёный | `strip-ok` | `#22c55e` |
| 4–5 | зелёно-жёлтый | `strip-warn` | `#a3e635` |
| 3 | оранжевый | `strip-orange` | `#f97316` |
| 2 | коралловый | `strip-coral` | `#fb7185` |
| 1 | огненно-рыжий | `strip-red` | `#ef4444` |
| ≤ 0 (день истечения и просрочено) | бордовый | `strip-overdue` | `#7f1d1d` |
| срока нет | серый/нейтральный | `strip-none` | `#94a3b8` |

Применяется к карточкам задач и отчётов на доске. Старые классы `priority-high` / `priority-medium` / `priority-low`, красящие полоску, заменяются на классы полоски. Приоритет остаётся как атрибут карточки (например, для возможного бейджа/сортировки), но полоску не красит.

### 2. Статусы и конверсия «задача ↔ отчёт»

**Селект статуса задачи (`#taskStatus`)** — три варианта: «Срочные», «В работе», «Отчёт».

При сохранении со статусом «Отчёт»:
- Новая запись → создаётся отчёт: `reportNumber = computeReportNumber()`, `status: 'active'`, поля (`title`, `description`, `priority`, `dueDate`, `assignedTo`, `createdBy`, `createdAt`) переносятся. Запись в задачи не создаётся.
- Существующая задача → конверсия: создать отчёт с теми же полями и сохранённым `createdAt`, затем удалить задачу (порядок: сначала создать, потом удалить — при ошибке ничего не теряется).

**Модалка отчёта** — появляется селект «Срочные / В работе / Отчёт» (по умолчанию «Отчёт»):
- «Отчёт» → обычное сохранение отчёта (без конверсии).
- «Срочно» / «В работе» → конверсия в задачу: создать задачу с теми же полями, `previousStatus: ''`, сохранить `createdAt`, затем удалить отчёт.

### 3. Кнопка «➕ Новая задача» → «Задача | Отчёт»

Кнопка `#addTaskBtn` открывает модалку задачи с переключателем вверху «Задача | Отчёт»:
- «Задача» → обычная форма задачи (с селектом статуса).
- «Отчёт» → поле статуса скрыто (подразумевается «Отчёт»), по сохранению создаётся отчёт.

Мобильная кнопка ➕ (`#mobileAddBtn`) — то же самое. Кнопка ➕ в шапке колонки «Отчёты» (`#addReportBtn`) остаётся как быстрый путь: открывает ту же модалку сразу в режиме «Отчёт».

### 4. Выполненные задачи и отчёты

При нажатии «✅ Выполнить» (`changeStatus` / `changeReportStatus`):
- записывается `completedAt` (ISO-время выполнения);
- записывается `completedLate: true/false` — сравнение точного времени выполнения с `dueDate` (выполнение позже `dueDate` = нарушение срока).

В архиве (табы «Задачи» и «Отчёты») выполненные записи:
- светло-зелёный фон (класс `archive-row-done`, фон `#f0fdf4`), полоска слева по классу;
- полоска: **зелёная**, если выполнено в срок; **бордовая**, если с нарушением; **серая**, если срока не было.

Правило для выполненного: бордовая полоска побеждает зелёную отметку фона (полоска остаётся бордовой).

### 5. Граничные случаи и данные

- Поля `completedAt` / `completedLate` — опциональные; старые записи без них обрабатываются как «без отметки» (полоска считается от текущего срока).
- Возврат из архива («Вернуть») — отметки `completedAt`/`completedLate` остаются в записи, но на доске полоска считается от текущего срока; при повторном выполнении отметки перезапишутся.
- Автопереход просроченных задач `in_progress → urgent` и уведомления о сроках не меняются.
- Excel-экспорт/импорт задач не меняется (отчёты — отдельная коллекция).
- Drag & Drop не меняется (задачи перетаскиваются между «Срочные» и «В работе»).
- Ошибки записи при конверсии — через существующий `alert` в `saveTask`/`saveReport`.

## Критерии приёмки

1. Карточка задачи/отчёта на доске окрашивается по сроку: >5 дней зелёная, 4–5 зелёно-жёлтая, 3 оранжевая, 2 коралловая, 1 огненно-рыжая, день истечения и просрочка — бордовая, без срока — серая.
2. В модалке задачи селект статуса содержит «Срочные / В работе / Отчёт»; сохранение со статусом «Отчёт» создаёт/превращает в отчёт с номером.
3. В модалке отчёта есть селект «Срочные / В работе / Отчёт»; выбор «Срочно»/«В работе» превращает отчёт обратно в задачу.
4. Кнопка «➕ Новая задача» (и мобильная ➕) открывает модалку с переключателем «Задача | Отчёт»; режим «Отчёт» создаёт отчёт.
5. Выполненная задача/отчёт в архиве имеет светло-зелёный фон; выполненные в срок — зелёная полоска, с нарушением срока — бордовая.
6. Старые записи без `completedAt`/`completedLate` не ломают рендер.
