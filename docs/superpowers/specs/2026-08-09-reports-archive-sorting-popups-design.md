# Дизайн: отчёты, архив, сортировка по сроку, модалки под курсором

Дата: 2026-08-09
Проект: task-tracker (PWA, Firebase Realtime Database + Auth, vanilla JS)

## Проблема / задача

Пользователь просит:
1. Сортировать задачи внутри каждой колонки по сроку выполнения (сверху — те, у кого срок истекает раньше).
2. На компьютерной версии всплывающие/модальные окна открывать под указателем мыши.
3. Заменить колонку «Выполнено» на блок «Отчёты» (еженедельные/ежемесячные отчёты). Выполненные задачи убирать в архив (модальное окно с поиском и выгрузкой).
4. Кнопки в архиве («открыть», «удалить» и др.) — серые с полной заливкой.

## Текущее состояние

- Доска Kanban: три колонки «Срочные» (urgent), «В работе» (in_progress), «Выполнено» (done).
- Задачи хранятся в `teams/<TEAM_ID>/tasks` (Firebase Realtime Database), слушаются через `on('value')`.
- Сортировка в колонке: приоритет (high → medium → low), затем по `createdAt` по убыванию (app.js `renderBoard`).
- Все модальные окна позиционируются по центру экрана (CSS `.modal` с flex-центрированием).
- Задачи можно перетаскивать между любыми колонками (drag & drop).
- Кнопка «✅ Выполнить» переводит задачу в статус `done` (остаётся на доске).

## Требования (после уточнений)

- Колонка «Выполнено» заменяется на блок «Отчёты».
- Блок «Отчёты» — такой же блок-колонка, как «Срочные»/«В работе», со списком отчётов.
- Карточка отчёта выглядит как карточка задачи: номер+месяц, срок, название.
- Отчёт: название, описание, месяц (например «февраль 2026»), номер (порядковый в рамках месяца), срок сдачи, автор.
- Создавать и редактировать отчёты могут все пользователи; удалять — только руководитель (admin).
- Выполненные задачи попадают в архив (модальное окно), а не остаются на доске.
- Архив — отдельное модальное окно, кнопка «Архив» рядом с «Настройки» и «Управление».
- В архиве: вкладки «Задачи»/«Отчёты», поиск по названию (у отчётов — и по номеру), кнопка «Выгрузить Excel».
- Руководитель видит весь архив, сотрудник — только свои (создал или назначен).
- В архиве: открыть, вернуть на доску, удалить (удаление — только руководитель).
- Кнопки в архиве — серые с полной заливкой.
- Сортировка внутри каждой колонки (и в «Отчётах») — по сроку выполнения по возрастанию; без срока — внизу. Приоритет на порядок не влияет.
- На ПК все модальные окна открываются под указателем мыши (по координатам клика, с подгонкой под вьюпорт). На телефоне — как сейчас, по центру.
- Drag & drop: задачи перетаскиваются только между «Срочные» и «В работе»; отчёты не перетаскиваются.

## Решения

### 1. Хранение отчётов

Отчёты хранятся в отдельной коллекции Firebase `teams/<TEAM_ID>/reports`.

Почему отдельно, а не в общей `tasks` с полем `type`:
- не ломает существующую логику задач (дедлайн-уведомления, делегирование, письма, экспорт задач);
- у задач и отчётов разные поля (у отчёта месяц и номер);
- отдельный listener и отдельный рендер, регрессионный риск минимален.

Структура отчёта:

```js
{
  id: string,               // generateId()
  title: string,            // название отчёта
  description: string,      // текст отчёта (опционально)
  period: 'YYYY-MM',        // месяц, напр. '2026-02'
  reportNumber: number,     // порядковый номер отчёта в этом месяце (№1, №2...)
  dueDate: string,          // срок сдачи (ISO, опционально)
  createdBy: string,        // логин автора
  status: 'active' | 'done',// 'done' = в архиве
  createdAt: string,        // ISO
  updatedAt: string         // ISO
}
```

Номер отчёта вычисляется при создании: `reportNumber = max(существующие номера за этот месяц) + 1`. Отображается как «№2 за февраль 2026».

### 2. Доска и колонки

- Колонки: `urgent` («Срочные»), `in_progress` («В работе»), `reports` («Отчёты»).
- Колонка `done` на доске удаляется; в `index.html` вместо неё — колонка `data-status="reports"`.
- В шапке колонки «Отчёты» — кнопка «➕» (новая отчёт).
- В форме задачи из выпадающего списка статусов убирается пункт «Выполнено» (остаются «Срочные» и «В работе»).
- Существующие задачи со статусом `done` автоматически считаются архивными (ничего мигрировать не нужно — они просто покажутся в архиве).

### 3. Архив

- Кнопка «🗂 Архив» в панели инструментов (рядом с «Настройки» и «Управление») и в мобильной панели.
- Модальное окно: вкладки «Задачи»/«Отчёты», строка поиска, кнопка «📤 Выгрузить Excel».
- Список задач в архиве: задачи со `status === 'done'`, доступные пользователю (admin — все, сотрудник — создал или назначен).
- Список отчётов в архиве: отчёты со `status === 'done'`, доступные пользователю (admin — все, сотрудник — создал).
- Поиск фильтрует по названию (у отчётов дополнительно по строке «№N за месяц»).
- Действия:
  - «⭕ Открыть» — модалка деталей;
  - «↩ Вернуть» — задача возвращается в `previousStatus` (по умолчанию `in_progress`), отчёт — в `status: 'active'`;
  - «🗑 Удалить» — только руководитель, с подтверждением.
- Кнопки архива — класс с серой полной заливкой (`btn-archived`).
- Выгрузка Excel: всё, что видно пользователю в архиве (обе вкладки), колонки по типу элемента.

### 4. Сортировка

В `renderBoard` и рендере отчётов:

```
задачи без срока -> вниз
сначала по dueDate по возрастанию (раньше — выше)
```

Приоритет больше не участвует в сортировке колонок.

### 5. Позиционирование модальных окон

- На ПК (media `min-width: 769px` или проверка `window.matchMedia('(pointer: fine)')`): `.modal-content` позиционируется по координатам клика (`e.clientX`, `e.clientY`), которые передаются в функцию открытия модалки. Содержимое подгоняется под вьюпорт: если окно вылезает за правый/нижний край — сдвигается влево/вверх; при необходимости может перевернуться над кнопкой.
- Все функции открытия модалок (`openTaskModal`, `showTaskDetails`, `showDelegateModal`, `openEditUserModal`, `openManagePanel`, `openReportModal`, `openArchive`) получают координаты точки открытия.
- На телефоне — текущее поведение (по центру, по ширине экрана), через CSS.

Реализация:
- `.modal` остаётся полноэкранным прозрачным слоем (ловит клики, закрытие по клику вне).
- `.modal-content` на ПК получает `position: fixed`, `left`/`top` по координатам клика (через inline-стиль), на мобильных медиа-запросах — центрирование по-прежнему.

### 6. Drag & drop

- Цели перетаскивания: только `.task-list` колонок `urgent` и `in_progress`.
- Колонка `reports` не принимает задачи.
- Карточки отчётов не имеют `draggable = true`.

## Затрагиваемые файлы

- `index.html` — колонка отчётов, кнопка «➕ Отчёт», кнопка «Архив», статус-селект без «Выполнено».
- `app.js` — listener отчётов, состояние `reports`, рендер отчётов, архив (модалка, поиск, выгрузка), позиционирование модалок, сортировка по сроку, ограничение drag & drop.
- `style.css` — стили колонки «Отчёты», кнопки «Архив», кнопок архива (серые, заливка), позиционирование модалок на ПК.

## Что не делаем (YAGNI)

- Отдельная страница/отчёт-конструктор (выбор задач в отчёт) — не требуется.
- Автоархивация отчётов по сроку — не требуется (архивация только по кнопке «✅»).
- Роли для отчётов шире «создать/редактировать все, удалять admin» — не требуется.

## Тестирование

Приложение без тестового фреймворка (vanilla JS + Firebase). Проверка вручную через `index.html`:
- вход admin/admin;
- создание задачи с разными сроками → порядок в колонках по сроку;
- «✅ Выполнить» → задача исчезает с доски, появляется в архиве (вкладка «Задачи»);
- создать отчёт («➕ Отчёт») → номер присваивается по месяцу, карточка в колонке «Отчёты»;
- «✅» на отчёте → отчёт в архиве (вкладка «Отчёты»);
- архив: поиск, возврат, удаление (админ), выгрузка Excel;
- модалки на ПК открываются под курсором, на мобильном разрешении — по центру.
